# Current state (what exists today)

_Update this file whenever behaviour or locations change. Last reviewed: 2026-10._

The repository is a pnpm/Turborepo workspace: the existing Next.js web app and its tests live in `apps/web`, the Expo mobile client lives in `apps/mobile`, and `packages/api-client` provides shared HTTP transport. Database migrations and Docker services remain at the root. Web feature code still includes pre-architecture locations; new work follows the target layout in `AGENTS.md`.

## Foundation code already in place

- `apps/mobile` — Expo Router app using Better Auth SecureStore sessions and the shared API transport. Native task, journal, notes, chat history, settings and home personality insights are available. The journal supports day navigation, a marked month calendar, per-day text drafts, attachments, voice notes and entry CRUD. The note editor has Markdown controls and autosave; chat has conversation history and per-chat actions. Personality insights reuse the shared, explainable analysis from tasks, journal entries and notes.
- `packages/api-client` — platform-independent JSON API transport used by web and mobile clients.
- `apps/web/src/config/env.ts` — typed env access (`publicEnv`, `serverEnv()`, `requireEnv`).
- `apps/web/src/config/features.ts` — feature flags per phase.
- `apps/web/src/server/providers/ai/*` — provider contract, registry, Groq/Puter stubs (`isAvailable()` is false).
- `apps/web/src/lib/composio/index.ts` — integration vocabulary and types.
- `apps/web/src/lib/ai/providers.ts` — client-safe list of AI options shown in the chat composer.
- `apps/web/src/types/index.ts` — shared type re-exports.

## Known gaps and shortcuts (be aware before building on them)

- Browser code writes through the generic `/api/v1/db` endpoint (RLS protects it) — rules like "recurring task creates the next one" live in the client. Moves to services in Phase 1–2.
- Tests: Vitest unit tests and database/RLS tests exist (UNT-33, see `docs/CONVENTIONS.md`), CI runs typecheck + unit tests + build, and a Playwright smoke/journey suite is written but needs a browser to run. No error monitoring yet (UNT-51, UNT-34).
- Admin "Usage" scans rows in memory (UNT-35).
- `profiles.personality` column is unused (the quiz was removed).
- Plan (`free`/`pro`) is stored but never enforced.
- Marketing "demo" pages are static illustrations, not the real app.
